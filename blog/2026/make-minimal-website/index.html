how to (not) make a minimal website

i’m sure all of us have at least considered making a website at least once. seriously, you’re missing out big time if you haven’t. i did, too, and the page you’re staring at right now is the result of that. how meta.

this post isn’t a tutorial. there’s plenty of those on the internet, and i don’t think i’d be adding any value if i wrote one myself. instead of larping, the post outlines my experience of making this website as your everyday 2026 high school dev.

# here be dragons

let’s start from the beginning. right, the beginning. being the lazy dev i am, i decided to write it in plain old html. it was tedious, alright. i guess html isn’t really meant for me. i trashed that source tree almost immediately.

that’s when i decided that i’d write the content in markdown. despite its name, it’s my favourite markUP language of all time. please laugh.

problem is, browsers don’t natively render markdown like they do html (justice for markdown!). naturally, any sane person would turn to all the beautiful static site generators that already exist. right, past me? RIGHT?!

# the birth of kami

here’s the plan i came up with. i would write all the actual site content in obsidian, and write a python program that would convert the markdown vault to a functional html site.

the only catch (i guess there’s always one lurking): what i thought would be a simple one-file script ended up mutating into almost a thousand lines of code split across several files.

thankfully, i open-sourced that repository so that anyone in the world can see my horribly written code. just in case, y’know! you can find it on my forge at n3rdium/kami.

tl;dr: kami (yes, with a lowercase ‘k’) takes an obsidian vault (and template html files so it knows what you want the page to look like) and spits out a functional website. it can even do this () and this:

i’ll be honest, kami is very “built for and around n3rdium.dev” in its current state. if it flies well, i plan to gradually shape it for general use.

# now what?

okay, i’ve built a little something to create simple websites “with ease”. all this time, i was so fixated on how i was going to build the site. i never thought about what i’m going to put there!

thus started my web content inspo-hunting arc (just kidding, kind of). i’m glad i fell into that rabbit hole. i discovered stuff like alive internet theory and neocities thanks to it, so it’s not something i regret.

at the end, i decided to make it a personal website (that will also serve as a nice portfolio when the time comes). oh, and of course, since i’ve already gone the markdown way, why not write a blog while i’m at it?

and of course, i decided to not add analytics, trackers or ads to the site. no wonder your uBO isn’t blocking anything (i hope) on this page.

# conclusion

and that is how this website came to be. it’s neither the best website, nor the most minimal. but it’s mine.

looking back, it wasn’t the greatest idea to reinvent the wheel by attempting to make my own static site generator. but i had fun, and i learned stuff, so i guess it was worth it?

until next time!
